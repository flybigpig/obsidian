## 概述
RenderThread 是 Android 5.0 (Lollipop) 引入的独立渲染线程，用于将渲染工作从 UI Thread 分离出来，提升应用流畅性。其核心流程为：sync → draw → GPU 渲染。

## DisplayList 构建流程详解
什么是 DisplayList
DisplayList（显示列表）是 Android 硬件加速渲染的核心机制，它是一个记录绘制指令的缓存数据结构，而不是立即执行绘制操作。当 View 需要重新绘制时，Android 会将绘制指令记录到 DisplayList 中，然后由 RenderThread 异步执行这些指令。

核心优势：

1. 分离记录和执行
	：UI Thread 只负责记录，RenderThread 负责执行
2. 缓存复用
	：View 未改变时可复用之前的 DisplayList
  3.异步渲染
	：不阻塞 UI Thread，提升流畅性
3. 优化空间
	：可在 RenderThread 进行裁剪、合并等优化

## DisplayList 的性能优化建议
```

┌─────────────────────────────────────────────────────────────────┐
│              DisplayList 性能优化最佳实践                        │
└─────────────────────────────────────────────────────────────────┘

1. 减少 DisplayList 重建频率
   ✓ 避免不必要的 invalidate()
   ✓ 使用属性动画 (ObjectAnimator) 而非 View 动画
   ✓ 属性变化优先使用 setAlpha()/setTranslation() 等
   ✗ 避免在 onDraw() 中创建对象
   ✗ 避免频繁改变 View 内容

2. 简化 View 层级
   ✓ 减少 View 嵌套深度 (< 10 层)
   ✓ 使用 ConstraintLayout 扁平化布局
   ✓ 合并相似的 View
   ✗ 避免不必要的 ViewGroup 包装

3. 使用 Hardware Layer 缓存
   view.setLayerType(LAYER_TYPE_HARDWARE, null)
   适用场景：
   ✓ 复杂的静态内容
   ✓ 需要频繁改变透明度/位移的 View
   ✓ 动画期间的缓存
   ✗ 不适用频繁变化的内容 (浪费内存)

4. 优化绘制操作
   ✓ 减少 Canvas.save()/restore() 调用
   ✓ 避免复杂的 Path 绘制
   ✓ 使用 clipRect 减少绘制区域
   ✓ 批量绘制相同类型的图形
   ✗ 避免在循环中创建 Paint 对象

5. 资源管理
   ✓ 复用 Bitmap 对象
   ✓ 使用适当的 Bitmap 格式 (RGB_565 vs ARGB_8888)
   ✓ 及时回收不用的资源
   ✗ 避免在 DisplayList 中引用大量大尺寸 Bitmap

6. 监控和调试
   工具：
   - GPU 过度绘制 (Settings → Developer options)
   - Profile GPU Rendering
   - Perfetto Trace (updateDisplayListIfDirty)
   - Systrace (Choreographer#draw)
     
```

**SYNC 阶段关键点：**

1. **数据同步**
    
    ：将 UI Thread 的更改同步到 RenderThread
    
2. **DisplayList 传递**
    
    ：传递记录的绘制指令
    
3. **属性更新**

4. **动画状态**
    
    ：更新动画的当前状态
    
5. **RenderNode 更新**
    
    ：更新渲染节点树结构
    
6. **线程解耦**
    
    ：UI Thread 可以继续准备下一帧，不阻塞

**GPU 渲染阶段关键点：**

1. **swapBuffers**
    
    ：交换前后缓冲区
    
2. **命令提交**
    
    ：将 OpenGL/Vulkan 指令提交到 GPU
    
3. **GPU Pipeline**
    
    ：
    

- 顶点着色器：处理顶点变换
    
- 片段着色器：处理像素着色
    
- 光栅化：将几何图形转换为像素
    
- 纹理采样：应用纹理
    
- 混合和深度测试
    

4. **异步渲染**
    
    ：RenderThread 提交命令后可继续工作
    
5. **Fence 同步**
    
    ：GPU Fence 信号通知渲染完成
    
6. **Buffer 提交**
    
    ：queueBuffer 将渲染结果提交给 SurfaceFlinger

## 性能优化要点

### 1. SYNC 阶段优化

- **减少 DisplayList 大小**
    
    ：简化 View 层级
    
- **避免频繁属性变更**
    
    ：批量更新属性
    
- **使用 Hardware Layer**
    
    ：缓存复杂视图
    
- **减少动画计算**
    
    ：使用插值器优化
    

### 2. DRAW 阶段优化

- **减少 Overdraw**
    
    ：避免多层重绘
    
- **启用裁剪优化**
    
    ：clipRect 减少绘制区域
    
- **合并绘制操作**
    
    ：使用 Canvas.saveLayer 合理
    
- **优化 Path 绘制**
    
    ：简化复杂路径
    
- **纹理复用**
    
    ：使用 Bitmap 缓存
    

### 3. GPU 渲染阶段优化

- **减少状态切换**
    
    ：批量渲染相同材质
    
- **优化 Shader**
    
    ：简化着色器逻辑
    
- **纹理压缩**
    
    ：使用 ETC2/ASTC 格式
    
- **避免 GPU 过载**
    
    ：控制绘制复杂度
    
- **使用 Vulkan**
    
    ：更高效的 GPU API (Android 7.0+)  
    

## 总结

RenderThread 的 **sync → draw → GPU 渲染** 流程是 Android 渲染架构的核心：

1. **SYNC 阶段**
    
    ：同步 UI Thread 和 RenderThread 的状态，实现线程解耦
    
2. **DRAW 阶段**
    
    ：遍历渲染树，构建 GPU 渲染指令，进行各种优化
    
3. **GPU 渲染阶段**
    
    ：异步执行 GPU 渲染，通过 Fence 同步，提交给 SurfaceFlinger
    

这三个阶段形成流水线，使得 UI Thread 可以提前准备下一帧，RenderThread 专注渲染，GPU 异步执行，最大化利用多核和 GPU 资源，实现高性能渲染
