你现在关注的 `ActivityRecord` 和 `ActivityStack` 是 Android 系统中**管理 Activity 生命周期、任务栈的核心数据结构**，属于 AMS（ActivityManagerService）的核心组件，我用最精简、和你之前关注的 BootAnimation / 系统服务逻辑衔接的方式解释：

---

# 一、一句话总结核心定位

- **ActivityRecord**：一个 `ActivityRecord` 对象 = 一个 Activity 实例的「系统侧档案」（记录 Activity 状态、启动参数、窗口信息等）；
- **ActivityStack**：一个 `ActivityStack` 对象 = 一个「Activity 任务栈」（管理一组 `ActivityRecord`，对应手机里的一个 “任务”，比如打开一个 App 就是一个栈）。

---

# 二、逐类极简解析（和你之前的上下文关联）

### 1. ActivityRecord

- **本质**：AMS 中描述单个 Activity 状态的「数据载体」，不是 Activity 本身（Activity 是 App 进程里的对象，`ActivityRecord` 是 system_server 进程里的对象）；
- **核心作用**：记录 Activity 的所有关键信息 —— 启动模式（standard/singleTop 等）、所属应用、窗口属性、生命周期状态（RESUMED/PAUSED/STOPPED）、Intent 启动参数等；
- **和你之前关注的关联**：当 SystemServer 启动完成、要退出 BootAnimation 并启动 Launcher（桌面）时，AMS 会为 Launcher 创建 `ActivityRecord`，并加入到前台栈中，这是你能看到桌面的核心步骤。

### 2. ActivityStack

- **本质**：管理 `ActivityRecord` 的「栈结构容器」，遵循 “后进先出”，对应 Android 的 “任务栈” 概念；
- **核心作用**：
    
    - 管理栈内 `ActivityRecord` 的入栈、出栈、切换（比如按返回键就是栈顶 `ActivityRecord` 出栈）；
    - 维护栈的状态（前台栈 / 后台栈），决定哪个 Activity 该显示；
    - 配合 WMS（WindowManagerService）完成窗口的显示 / 隐藏；
    
- **关键补充**：
    
    - 早期 Android 只有一个 `ActivityStack`，后来为了适配分屏、多窗口，扩展出 `ActivityStackSupervisor`（栈管理器），管理多个 `ActivityStack`；
    - 当 Launcher 启动后，它的 `ActivityRecord` 会被放在 `ActivityStack` 的栈顶，成为前台显示的 Activity，这也是 BootAnimation 最终退出的 “终点”。
    

---

# 三、和你之前关注的逻辑衔接（完整链路）

结合你之前问的 BootAnimation、EXIT_PROP_NAME、LocalServices，完整的系统启动→显示桌面链路：

1. SystemServer 启动 AMS/WMS/VR 服务等核心服务；
2. AMS 初始化 `ActivityStackSupervisor` 和默认的 `ActivityStack`；
3. SystemServer 通知 BootAnimation 退出（设置 EXIT_PROP_NAME=1）；
4. AMS 为 Launcher 创建 `ActivityRecord`，并将其入栈到前台 `ActivityStack`；
5. WMS 配合 AMS，将 Launcher 的窗口显示到屏幕（SurfaceFlinger 切换图层）；
6. BootAnimation 线程退出，用户看到 Launcher 桌面（栈顶 `ActivityRecord` 对应的 Activity 显示）。

---

# 四、核心区别（避免混淆）

表格

|类|核心角色|所在进程|类比|
|---|---|---|---|
|ActivityRecord|单个 Activity 的 “档案”|system_server|酒店里的 “房间卡”|
|ActivityStack|管理 Activity 的 “栈”|system_server|酒店里的 “楼层”|
|Activity|App 里的实际页面对象|应用进程|酒店里的 “房间”|

---

### 总结

1. `ActivityRecord` 是 AMS 对单个 Activity 的 “抽象描述”，`ActivityStack` 是管理这些描述的 “栈容器”；
2. 二者都是 system_server 进程内的核心数据结构，不走跨进程（和 LocalServices 逻辑一致）；
3. 它们是 BootAnimation 退出后，系统能正常显示 Launcher / 其他 App 的核心底层支撑。
