当Launcher准备就绪时，系统会通过一系列协调机制来关闭开机动画，确保用户能平滑地进入桌面界面。这一过程主要由系统核心服务（如ActivityManagerService和WindowManagerService）协同完成，而非由Launcher应用直接控制。

### 关闭开机动画的关键流程

1. ‌**Launcher启动通知系统**‌：当Launcher应用的主Activity（即桌面界面）被启动并进入前台后，其主线程会在消息队列空闲时，向ActivityManagerService（AMS）发送一个“空闲通知”。
2. ‌**AMS判断系统启动完成**‌：AMS接收到这个通知后，会检查系统是否正处于启动过程中（通过`mBooting`标志位）。如果此时系统尚未完成启动（`mBooting`为`true`），AMS会将`mBooting`设为`false`，并标记系统已完全启动（`mBooted`设为`true`）。
3. ‌**触发屏幕启用与动画关闭**‌：AMS会调用`enableScreenAfterBoot()`方法。该方法最终会通知WindowManagerService（WMS）执行实际的屏幕启用操作。
4. ‌**WMS关闭开机动画**‌：WMS在收到启用屏幕的指令后，会执行`performEnableScreen()`方法。在此方法中，WMS会检查所有关键窗口（如Launcher窗口、状态栏窗口）是否已准备就绪。一旦确认所有条件满足，WMS就会调用内部方法，最终停止由`bootanimation`进程播放的开机动画，并显示Launcher的桌面界面。

### 与Launcher动画的区别

需要区分的是，您提到的“Launcher准备就绪”关闭的是‌**系统开机动画**‌（即从开机到看到桌面的动画）。而公开资料中提到的“关闭启动App和关闭App的动画”，是指在Launcher桌面‌**内部**‌，点击应用图标启动应用或从最近任务中关闭应用时，应用窗口切换的动画效果。这两者是不同层级的动画：

- ‌**系统开机动画**‌：由`bootanimation`进程播放，由AMS/WMS在系统启动完成后关闭。
- ‌**Launcher内部动画**‌：由Launcher应用（如Launcher3）自身控制，可通过修改其代码（如添加`Intent.FLAG_ACTIVITY_NO_ANIMATION`）来关闭，以提升流畅度‌6。

综上所述，当Launcher准备就绪时，是通过向AMS发送空闲通知，触发AMS与WMS的交互，最终由WMS负责停止开机动画，完成从开机画面到桌面的切换。‌

    /**
     * 处理Activity空闲事件
     * 
     * 当Activity进入空闲状态时调用此方法，主要负责：
     * 1. 清除调用者身份标识以获得系统权限
     * 2. 查找对应的Activity堆栈
     * 3. 调用监督器处理Activity空闲状态
     * 4. 根据需要清除性能分析器
     * 5. 最后恢复原始调用者身份标识
     * 
     * @param token Activity的Binder令牌
     * @param config Activity的配置信息
     * @param stopProfiling 是否停止性能分析
     */
    public final void activityIdle(IBinder token, Configuration config, boolean stopProfiling) {
        // 保存并清除调用者身份标识，以确保后续操作具有系统权限
        final long origId = Binder.clearCallingIdentity();
        try {
            WindowProcessController proc = null;
            
            // 在全局锁保护下进行Activity空闲处理
            synchronized (mGlobalLock) {
                // 根据token查找对应的Activity堆栈
                ActivityStack stack = ActivityRecord.getStackLocked(token);
                if (stack == null) {
                    return;
                }
                
                // 调用监督器处理Activity空闲状态
                final ActivityRecord r = mStackSupervisor.activityIdleInternalLocked(token,
                        false /* fromTimeout */, false /* processPausingActivities */, config);
                if (r != null) {
                    proc = r.app;
                }
                
                // 如果需要停止性能分析且进程存在，则清除分析器
                if (stopProfiling && proc != null) {
                    proc.clearProfilerIfNeeded();
                }
            }
        } finally {
            // 恢复原始调用者身份标识
            Binder.restoreCallingIdentity(origId);
        }
    }

    /**
     * 处理Activity空闲状态的内部方法
     * 
     * 当Activity进入空闲状态时调用此方法，负责处理Activity生命周期相关的清理工作，
     * 包括停止、销毁Activity，处理用户切换，以及触发垃圾回收等操作。
     * 
     * @param token Activity的Binder令牌
     * @param fromTimeout 是否由于超时触发
     * @param processPausingActivities 是否处理暂停中的Activity
     * @param config 配置信息
     * @return ActivityRecord 返回处理的Activity记录
     */
    final ActivityRecord activityIdleInternalLocked(final IBinder token, boolean fromTimeout,
            boolean processPausingActivities, Configuration config) {
        if (DEBUG_ALL) Slog.v(TAG, "Activity idle: " + token);

        ArrayList<ActivityRecord> finishes = null;
        ArrayList<UserState> startingUsers = null;
        int NS = 0;
        int NF = 0;
        boolean booting = false;
        boolean activityRemoved = false;

        // 获取指定token对应的Activity记录
        ActivityRecord r = ActivityRecord.forTokenLocked(token);
        if (r != null) {
            if (DEBUG_IDLE) Slog.d(TAG_IDLE, "activityIdleInternalLocked: Callers="
                    + Debug.getCallers(4));
            mHandler.removeMessages(IDLE_TIMEOUT_MSG, r);
            r.finishLaunchTickingLocked();
            if (fromTimeout) {
                reportActivityLaunchedLocked(fromTimeout, r, INVALID_DELAY,
                        -1 /* launchState */);
            }

            // 处理配置更新的竞态条件问题
            if (config != null) {
                r.setLastReportedGlobalConfiguration(config);
            }

            // 标记Activity为空闲状态
            r.idle = true;

            // 检查是否可以完成系统启动过程
            if ((mService.isBooting() && mRootActivityContainer.allResumedActivitiesIdle())
                    || fromTimeout) {
                booting = checkFinishBootingLocked();
            }

            // 清除重新启动标志
            r.mRelaunchReason = RELAUNCH_REASON_NONE;
        }

        // 处理所有恢复的Activity都空闲的情况
        if (mRootActivityContainer.allResumedActivitiesIdle()) {
            if (r != null) {
                mService.scheduleAppGcsLocked();
            }

            // 释放启动Activity的唤醒锁
            if (mLaunchingActivityWakeLock.isHeld()) {
                mHandler.removeMessages(LAUNCH_TIMEOUT_MSG);
                if (VALIDATE_WAKE_LOCK_CALLER &&
                        Binder.getCallingUid() != Process.myUid()) {
                    throw new IllegalStateException("Calling must be system uid");
                }
                mLaunchingActivityWakeLock.release();
            }
            mRootActivityContainer.ensureActivitiesVisible(null, 0, !PRESERVE_WINDOWS);
        }

        // 原子性地获取所有需要处理的Activity列表
        final ArrayList<ActivityRecord> stops = processStoppingActivitiesLocked(r,
                true /* remove */, processPausingActivities);
        NS = stops != null ? stops.size() : 0;
        if ((NF = mFinishingActivities.size()) > 0) {
            finishes = new ArrayList<>(mFinishingActivities);
            mFinishingActivities.clear();
        }

        // 处理待启动的用户列表
        if (mStartingUsers.size() > 0) {
            startingUsers = new ArrayList<>(mStartingUsers);
            mStartingUsers.clear();
        }

        // 停止所有计划停止但一直在等待下一个Activity启动的Activity
        for (int i = 0; i < NS; i++) {
            r = stops.get(i);
            final ActivityStack stack = r.getActivityStack();
            if (stack != null) {
                if (r.finishing) {
                    stack.finishCurrentActivityLocked(r, ActivityStack.FINISH_IMMEDIATELY, false,
                            "activityIdleInternalLocked");
                } else {
                    stack.stopActivityLocked(r);
                }
            }
        }

        // 完成所有计划完成但一直在等待下一个Activity启动的Activity
        for (int i = 0; i < NF; i++) {
            r = finishes.get(i);
            final ActivityStack stack = r.getActivityStack();
            if (stack != null) {
                activityRemoved |= stack.destroyActivityLocked(r, true, "finish-idle");
            }
        }

        // 处理用户切换完成
        if (!booting) {
            if (startingUsers != null) {
                for (int i = 0; i < startingUsers.size(); i++) {
                    mService.mAmInternal.finishUserSwitch(startingUsers.get(i));
                }
            }
        }

        // 触发应用程序垃圾回收
        mService.mH.post(() -> mService.mAmInternal.trimApplications());

        // 如果有Activity被移除，则恢复焦点栈顶的Activity
        if (activityRemoved) {
            mRootActivityContainer.resumeFocusedStacksTopActivities();
        }

        return r;
    }

    /**
     * 检查并完成系统启动过程
     * 
     * 此方法用于处理系统启动完成的相关逻辑，包括：
     * 1. 设置系统启动状态为已完成
     * 2. 如果系统首次启动完成，启用屏幕显示
     * 3. 触发启动完成后的回调处理
     * 
     * @return boolean 返回系统是否处于启动状态
     */
    private boolean checkFinishBootingLocked() {
        // 获取当前系统启动状态
        final boolean booting = mService.isBooting();
        boolean enableScreen = false;
        
        // 标记系统启动过程已完成
        mService.setBooting(false);
        
        // 如果系统尚未标记为已启动，则标记为已启动并准备启用屏幕
        if (!mService.isBooted()) {
            mService.setBooted(true);
            enableScreen = true;
        }
        
        // 如果系统正在启动或需要启用屏幕，则执行启动完成后的处理
        if (booting || enableScreen) {
            mService.postFinishBooting(booting, enableScreen);
        }
        
        return booting;
    }

void postFinishBooting(boolean finishBooting, boolean enableScreen) {

        }

            mInternal.enableScreenAfterBoot(isBooted());

    });
