```java
public final class ProcessRecord {
    // AMS 管理的进程信息
    final int pid;
    final String processName;
    final int uid;
    
    // 关键：双向链接
    // 1. AMS 持有该进程的所有 Activity
    final ArrayList<ActivityRecord> activities = new ArrayList<>();
    
    // 2. 指向 ATMS 的接口（用于回调）
    IActivityTaskManager mActivityTaskManager;
    
    // 设置 ATMS 引用
    public void setActivityTaskManager(IActivityTaskManager atm) {
        mActivityTaskManager = atm;
    }
    
    // 添加 Activity（由 ATMS 调用）
    public void addActivity(ActivityRecord r) {
        synchronized (activities) {
            activities.add(r);
        }
        
        // 更新进程状态
        updateProcessState();
    }
}
```

## **5. 全局锁机制**

### **共享的全局锁对象**

```java
// 文件：/frameworks/base/services/core/java/com/android/server/am/ActivityManagerGlobalLock.java

/**
 * 这是 ATMS 和 AMS 共享的全局锁
 * 确保对共享数据结构（如 ProcessRecord、ActivityRecord）的访问是线程安全的
 */
public class ActivityManagerGlobalLock {
    // 实际的锁对象
    private final Object mLock = new Object();
    
    public Object getLock() {
        return mLock;
    }
}

// 在 ATMS 中
public class ActivityTaskManagerService {
    // 持有全局锁
    private final ActivityManagerGlobalLock mGlobalLock;
    
    public ActivityTaskManagerService(Context context) {
        // 创建全局锁实例
        mGlobalLock = new ActivityManagerGlobalLock();
    }
    
    void someMethod() {
        synchronized (mGlobalLock.getLock()) {
            // 访问共享数据
            // AMS 可能在另一个线程中也持有同样的锁
        }
    }
}

// 在 AMS 中
public class ActivityManagerService {
    // 引用同一个全局锁
    private final ActivityManagerGlobalLock mGlobalLock;
    
    // 在设置 ATMS 时同步锁对象
    public void setActivityTaskManager(ActivityTaskManagerService atm) {
        mActivityTaskManager = atm;
        // 确保使用同一个锁实例
        mGlobalLock = atm.getGlobalLock();
    }
}
```

## **8. 设计模式和架构思考**

### **为什么这样设计？**

1. **循环引用但职责清晰**
   - AMS 和 ATMS 相互持有引用，但**不是强耦合**
   - 每个服务通过**明确定义的接口**访问对方功能
   - 例如：ATMS 只调用 `ams.checkPermission()`，不关心具体实现

2. **数据所有权明确**
   - **AMS 拥有**：`ProcessRecord`、`ServiceRecord`、`BroadcastRecord`
   - **ATMS 拥有**：`ActivityRecord`、`Task`、`TaskStack`
   - **交叉引用**：`ProcessRecord.activities` ↔ `ActivityRecord.app`

3. **通过接口解耦**
   ```java
   // ATMS 实际上是通过接口访问 AMS
   public interface IActivityManagerService {
       int checkPermission(String permission, int pid, int uid);
       ProcessRecord getProcessRecord(String processName, int uid);
       void updateOomAdjLocked(ProcessRecord app);
   }
   
   // AMS 实现这个接口
   ```

### **初始化时序问题解决**

1. **分阶段初始化**
   ```java
   // 第一阶段：创建实例
   AMS ams = new AMS();
   ATMS atms = new ATMS();
   
   // 第二阶段：建立引用
   atms.initialize(ams);  // ATMS 获得 AMS 引用
   ams.setActivityTaskManager(atms);  // AMS 获得 ATMS 引用
   
   // 第三阶段：完成初始化
   ams.systemReady();
   atms.systemReady();
   ```

2. **延迟初始化某些组件**
   ```java
   // 在 ATMS.initialize() 中初始化需要 AMS 的组件
   public void initialize(ActivityManagerService ams) {
       mActivityManagerService = ams;
       
       // 现在可以初始化依赖 AMS 的组件
       mTaskSupervisor.initialize();
       mRootWindowContainer.initialize();
   }
   ```

### **常见问题**

1. **空指针异常**：在 `initialize()` 调用前访问对方服务
2. **死锁风险**：两个服务相互调用时注意锁顺序
3. **内存泄漏**：循环引用需要正确的清理机制

这种相互引用的设计是 Android 10 架构演进的关键，它实现了：
- **功能分离**：前台/后台逻辑解耦
- **代码可维护**：每个服务代码量减少
- **性能优化**：专门的模块处理专门的任务
- **未来扩展**：便于添加新的窗口管理功能
