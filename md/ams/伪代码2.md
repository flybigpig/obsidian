# AMS & ATMS 核心逻辑伪代码（Android 10+ 标准流程）

为了让你直观理解 AMS（进程管理）和 ATMS（页面/任务栈管理）的核心分工与联动逻辑，我基于 Android 源码的核心流程，编写了**简化伪代码**（聚焦「启动Activity」这个最核心场景），覆盖「ATMS 发起启动请求 → AMS 启动进程 → ATMS 完成Activity启动」的全链路，标注关键联动点和核心逻辑分支。

说明：伪代码省略了 Binder 跨进程调用、权限校验、异常处理等细节，仅保留核心逻辑，重点体现「ATMS 管页面、AMS 管进程」的分工。

---

## 一、整体核心流程（伪代码总览）

```Plain
// 场景：用户点击应用图标，启动目标Activity（无进程）
1. 桌面应用调用 startActivity() → 跨进程调用 ATMS.startActivity()
2. ATMS 校验Activity/任务栈 → 检测到无进程 → 调用 AMS.startProcess()
3. AMS 通知 Zygote 孵化进程 → 进程启动后回调 ATMS
4. ATMS 完成Activity入栈/生命周期 → 联动 WMS 创建窗口 → 页面显示
```

## 二、ATMS（ActivityTaskManagerService）核心伪代码

```Java
/**
 * ATMS 核心类：仅负责 Activity/任务栈管理，无进程操作能力
 */
public class ActivityTaskManagerService {
    // 核心属性：与AMS/WMS的联动接口
    private IActivityManagerInternal mAmInternal; // 调用AMS的内部接口
    private WindowManagerService mWmService;     // 调用WMS创建窗口
    private RootWindowContainer mRootWindowContainer; // 任务栈根容器

    // ===================== 核心方法：启动Activity（所有启动入口） =====================
    public int startActivity(Intent intent, ActivityInfo activityInfo, int userId) {
        // 步骤1：校验Activity合法性（启动模式、权限、Task栈规则）
        if (!checkActivityValid(activityInfo)) {
            return -1; // 校验失败（如权限不足、Activity不存在）
        }

        // 步骤2：创建ActivityRecord（描述Activity的状态）
        ActivityRecord activityRecord = new ActivityRecord(intent, activityInfo, userId);

        // 步骤3：检测目标应用是否有进程（核心：向AMS发起查询）
        ProcessRecord processRecord = mAmInternal.getProcessRecord(activityInfo.packageName);
        if (processRecord == null || !processRecord.isAlive()) {
            // 3.1 无进程 → 向AMS发起进程启动请求
            mAmInternal.startProcess(activityInfo.packageName, activityInfo.uid);
            // 3.2 等待进程启动完成（AMS启动进程后会回调attachApplication()）
            waitForProcessStarted(activityInfo.packageName);
        }

        // 步骤4：进程就绪 → 处理Activity入栈（Task栈管理）
        TaskRecord taskRecord = getOrCreateTaskRecord(activityRecord); // 获取/创建Task栈
        mRootWindowContainer.addActivityToTask(activityRecord, taskRecord); // Activity入栈

        // 步骤5：执行Activity生命周期（onCreate→onStart→onResume）
        handleActivityLifecycle(activityRecord, LifecycleState.RESUME);

        // 步骤6：联动WMS创建窗口（Activity显示的核心）
        mWmService.addWindow(activityRecord, activityInfo.windowLayout);

        // 步骤7：更新Task栈状态（如移到前台）
        moveTaskToFront(taskRecord);

        return 0; // 启动成功
    }

    // ===================== 核心方法：处理Activity生命周期 =====================
    private void handleActivityLifecycle(ActivityRecord activityRecord, LifecycleState state) {
        // 向应用进程的ActivityThread发送生命周期指令
        IApplicationThread appThread = activityRecord.processRecord.appThread;
        switch (state) {
            case CREATE:
                appThread.scheduleLaunchActivity(activityRecord); // 触发onCreate
                break;
            case START:
                appThread.scheduleStartActivity(activityRecord);   // 触发onStart
                break;
            case RESUME:
                appThread.scheduleResumeActivity(activityRecord);  // 触发onResume
                break;
            case PAUSE:
                appThread.schedulePauseActivity(activityRecord);   // 触发onPause
                break;
            case DESTROY:
                appThread.scheduleDestroyActivity(activityRecord); // 触发onDestroy
                break;
        }
    }

    // ===================== 核心方法：AMS进程启动完成后的回调 =====================
    public void attachApplication(IApplicationThread appThread, String packageName) {
        // 1. 绑定应用进程的ActivityThread到ProcessRecord
        ProcessRecord processRecord = mAmInternal.getProcessRecord(packageName);
        processRecord.appThread = appThread;
        // 2. 唤醒等待的startActivity流程（继续完成Activity启动）
        notifyProcessStarted(packageName);
    }

    // ===================== 辅助方法：Task栈管理 =====================
    private TaskRecord getOrCreateTaskRecord(ActivityRecord activityRecord) {
        // 根据启动模式（如singleTask、standard）获取已有Task或新建Task
        TaskRecord task = mRootWindowContainer.findTaskByActivity(activityRecord);
        if (task == null) {
            task = new TaskRecord(activityRecord);
            mRootWindowContainer.addTask(task);
        }
        return task;
    }

    // 其他核心方法简化（仅保留签名）
    public void finishActivity(ActivityRecord activityRecord) { /* 移除Activity、执行onDestroy、通知AMS调整进程优先级 */ }
    public void moveTaskToFront(TaskRecord taskRecord) { /* 将Task移到前台、联动WMS置顶窗口 */ }
}
```

## 三、AMS（ActivityManagerService）核心伪代码

```Java
/**
 * AMS 核心类：仅负责进程/权限/Service管理，无页面/Task栈操作能力
 */
public class ActivityManagerService {
    // 核心属性：进程管理、Zygote通信、ATMS回调接口
    private ProcessList mProcessList; // 管理所有运行中的进程
    private ZygoteProcess mZygoteProcess; // 与Zygote通信孵化进程
    private IActivityTaskManagerInternal mAtmInternal; // 回调ATMS的接口

    // ===================== 核心方法：启动应用进程 =====================
    public int startProcess(String packageName, int uid) {
        // 步骤1：校验进程启动权限（如是否允许创建进程）
        if (!checkProcessPermission(packageName, uid)) {
            return -1;
        }

        // 步骤2：创建ProcessRecord（描述进程状态）
        ProcessRecord processRecord = new ProcessRecord(packageName, uid);
        mProcessList.addProcess(processRecord);

        // 步骤3：通知Zygote孵化进程（核心：Zygote是Android进程的父进程）
        String processName = getProcessName(packageName);
        int pid = mZygoteProcess.forkAndSpecialize(processName, uid); // 孵化进程
        if (pid < 0) {
            return -1; // 进程启动失败
        }

        // 步骤4：更新ProcessRecord（记录PID、状态）
        processRecord.pid = pid;
        processRecord.state = ProcessState.STARTING;

        // 步骤5：等待进程初始化完成（应用进程启动ActivityThread后会attach）
        waitForProcessAttach(pid);

        // 步骤6：进程就绪 → 回调ATMS（通知可以继续启动Activity）
        mAtmInternal.attachApplication(processRecord.appThread, packageName);

        // 步骤7：设置进程优先级（默认前台进程）
        setProcessOomAdj(processRecord, OomAdj.FOREGROUND);

        return 0; // 进程启动成功
    }

    // ===================== 核心方法：调整进程优先级（OOM_ADJ） =====================
    public void setProcessOomAdj(ProcessRecord processRecord, int oomAdj) {
        // 更新进程的oom_adj值（决定内存不足时的回收顺序）
        processRecord.oomAdj = oomAdj;
        // 通知内核调整进程优先级
        updateKernelProcessPriority(processRecord.pid, oomAdj);
    }

    // ===================== 核心方法：杀死进程 =====================
    public void killProcess(ProcessRecord processRecord, String reason) {
        // 1. 通知ATMS清理该进程的Task栈/Activity
        mAtmInternal.cleanUpApplicationRecord(processRecord);
        // 2. 杀死进程（向内核发送信号）
        killProcessByPid(processRecord.pid);
        // 3. 从进程列表移除
        mProcessList.removeProcess(processRecord);
    }

    // ===================== 辅助方法：查询进程 =====================
    public ProcessRecord getProcessRecord(String packageName) {
        // 从ProcessList中查询指定包名的进程
        return mProcessList.findProcessByPackageName(packageName);
    }

    // 其他核心方法简化（仅保留签名）
    public int checkPermission(String permission, int uid) { /* 校验应用权限 */ }
    public void bindService(Intent intent, ServiceConnection connection) { /* 绑定Service */ }
    public void sendBroadcast(Intent intent) { /* 发送广播 */ }
}
```

## 四、核心联动关键节点（伪代码标注）

|   |   |   |   |
|---|---|---|---|
|联动场景|ATMS 侧代码|AMS 侧代码|核心作用|
|查询进程是否存在|`mAmInternal.getProcessRecord(pkg)`|`getProcessRecord(pkg)`|检测目标应用是否有运行的进程|
|启动进程|`mAmInternal.startProcess(pkg, uid)`|`startProcess(pkg, uid)`|通知AMS孵化新进程|
|进程启动完成回调|`attachApplication(appThread, pkg)`|`mAtmInternal.attachApplication(...)`|通知ATMS进程就绪，继续启动Activity|
|调整进程优先级|`mAmInternal.setProcessOomAdj(...)`|`setProcessOomAdj(process, adj)`|应用退后台时降低进程优先级|

## 五、伪代码核心总结（面试/理解关键点）

1. **分工明确**：
    
    1. ATMS 的核心逻辑是「Activity入栈、生命周期管理、联动WMS创窗口」，所有进程相关操作均通过 `mAmInternal` 调用AMS；
        
    2. AMS 的核心逻辑是「进程孵化、优先级调整、权限校验」，进程就绪后通过 `mAtmInternal` 回调ATMS。
        
2. **联动核心**：
    

3. 二者通过「内部Binder接口」（`IActivityManagerInternal`/`IActivityTaskManagerInternal`）通信，无直接强引用，实现解耦。
    

4. **启动流程核心**：
    

5. ATMS 是启动Activity的「入口」，AMS 是「进程支撑」，缺了AMS的进程启动，ATMS无法完成Activity的最终启动。
    

6. **无交叉操作**：
    

7. ATMS 不碰「进程/权限/Service」，AMS 不碰「Activity/Task栈/窗口」，严格遵循「单一职责」。
    

这套伪代码覆盖了 AMS/ATMS 最核心的交互逻辑，可直接用于面试时「口述启动流程+手写核心伪代码」，是理解二者分工的最优简化版本！
