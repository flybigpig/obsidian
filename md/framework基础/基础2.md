### 1.编写Android.mk

`#`前不要用空格隔开，

```
LOCAL_PATH := $(call my-dir)# 获取当前模块源码目录  
include $(CLEAR_VARS)# 清空之前的LOCAL_XXX变量，避免模块冲突  
LOCAL_SRC_FILES := thread_posix.c   # 要编译的c文件  
LOCAL_MODULE := linux_thread  // 编译后的文件名  
LOCAL_SHARED_LIBRARIES :=liblog  // 依赖的库  
LOCAL_PRELINK_MODULE := false  
include $(BUILD_EXECUTABLE)# 告诉编译系统：当前模块要被编译成一个可执行程序
```

## .mk文件编写

编写的时候注意空格不然可能会报错![在这里插入图片描述](https://mmbiz.qpic.cn/mmbiz_png/NaxKxZyPlpbNzuaK0pLsw8SRm41UdaZnBmficzkOodnicSAxpqcmxF3spicZWrIsB4Bb2Ds9szlWhB4el4TLOSzMianM3VxUY26lMAoAGXyiaOh0/640?wx_fmt=png&from=appmsg&watermark=1&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=6)

```
# 固定开头：定义当前模块目录（整个 mk 文件只需要定义一次 LOCAL_PATH）  
LOCAL_PATH := $(call my-dir)  
  
# ========== 第一个模块：android_thread（可执行程序） ==========  
include $(CLEAR_VARS)  # 清空 LOCAL_XXX 变量，为新模块做准备  
  
# 源码文件（注意：最后一行不能加反斜杠 \，否则会报语法错误）  
LOCAL_SRC_FILES := MyThread.cpp \  
                   Main.cpp  # 去掉末尾多余的 \  
  
# 依赖的动态库  
LOCAL_SHARED_LIBRARIES := libandroid_runtime \  
                          libcutils \  
                          libutils \  
                          liblog  # 去掉多余空格，保持格式整洁  
  
LOCAL_MODULE := android_thread  # 模块名1  
LOCAL_PRELINK_MODULE := false  
  
include $(BUILD_EXECUTABLE)  # 编译为可执行程序  
  
# ========== 第二个模块：linux_thread（可执行程序） ==========  
include $(CLEAR_VARS)  # 必须再次清空变量，避免和上一个模块冲突  
  
LOCAL_SRC_FILES := thread_posix.c  # 单个文件无需反斜杠  
  
LOCAL_MODULE := linux_thread  # 模块名2  
LOCAL_SHARED_LIBRARIES := liblog  
LOCAL_PRELINK_MODULE := false  
  
include $(BUILD_EXECUTABLE)  # 编译为可执行程序
```

## 安卓日志

`MainLog` 有明确的 5 个级别（Verbose/Debug/Info/Warning/Error），主要用于开发调试。、`EventLog`属于 Android 的事件日志体系，而非普通 Logcat 日志；

### 1.c++中打印logcat日志

```
#define LOG_NDEBUG 1 //放开日志

#include <utils/Log.h> // 导包  
ALOGD("testServer1111  start main"); // 使用
```

```
#include<utils/CallStack.h>  
  
  
CallStack stack;  
stack.update();

``` 
### 高版本aosp打印antive CallStack堆栈遇到问题

新版本aosp上打印CallStack编译会报错：

error: undefined symbol: android::CallStack::CallStack(char const*, int) 这块解决参考了马哥文章：

[https://mp.weixin.qq.com/s/w2BL8BgDQ_h4NzrHlpO_yg](https://mp.weixin.qq.com/s?__biz=MzkzOTQ4NDUyNg==&mid=2247488222&idx=1&sn=644aa8a26ab6e06ad05be13c352e5ec1&scene=21#wechat_redirect)

需求在 frameworks/native/services/inputflinger/dispatcher/InputDispatcher.cpp 代码的openInputChannelPair进行堆栈打印

```
status_t openInputChannelPair(const std::string& name, std::shared_ptr<InputChannel>& serverChannel,  
                              std::unique_ptr<InputChannel>& clientChannel) {

 cs.update();  
 cs.log("INTEL-MESA");  
 //省略  
    return result;  
}
```

可以看到这里确实在编译InputDispatcher.cpp:356时候发现引入ld不到libutilscallstack库，所以导致无法找到符号表报错，但是明明我们确实cpp编译的bp中加入了相关的libutilscallstack，那这种应该怎么解决呢？ 其实这种问题大家一定要认真看编译的报错日志第一行，看看具体编译哪个目标时候在报错：

[ 86% 211/244] //frameworks/native/services/inputflinger:libinputflinger link libinputflinger.so

大家注意这里是在编译libinputflinger.so时候报错的，那么大家就可以考虑找到libinputflinger的编译Android.bp，然后考虑加入libutilscallstack
