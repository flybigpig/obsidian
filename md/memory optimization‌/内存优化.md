## 一、内存优化核心策略

### 1.1 应用层优化策略

| 优化方向 | 具体措施 | 代码示例 |
|---------|---------|---------|
| **对象池化** | 避免频繁创建/销毁对象 | `ObjectPool.obtain()` / `recycle()`  |
| **内存感知加载** | 根据内存压力动态调整资源质量 | `MemoryAwareLoader` 分级加载  |
| **弱引用使用** | 避免内存泄漏 | `WeakReference<Context>` |
| **图片优化** | 采样率压缩、格式选择、及时回收 | `BitmapFactory.Options.inSampleSize` |
| **字符串优化** | 使用 StringBuilder、字符串池 | `StringOptimizer.internString()`  |
| **协程作用域管理** | 自动取消协程避免泄漏 | `viewModelScope` / `WhileUiSubscribed`  |

### 1.2 代码级优化示例

```kotlin
// 1. 内存感知加载器 
class MemoryAwareLoader {
    fun loadResourceWithMemoryAware(request: LoadRequest) {
        when (getCurrentMemoryPressure()) {
            MemoryPressure.CRITICAL -> {
                // 只加载关键资源
                if (request.isCritical) loadWithMinimalMemory(request)
                else scheduleForLater(request)
            }
            MemoryPressure.HIGH -> {
                // 降低资源质量
                val reduced = request.copy(quality = request.quality * 0.7f)
                loadResource(reduced)
            }
            else -> loadResource(request)  // 正常加载
        }
    }
}

// 2. 对象池实现 
object ObjectPool {
    private val pools = ConcurrentHashMap<String, Queue<Any>>()
    
    fun <T> obtain(size: Int, factory: () -> T): T {
        val key = "${factory::class.java.simpleName}_$size"
        return (pools[key]?.poll() as? T) ?: factory()
    }
    
    fun <T> recycle(obj: T) {
        val key = generateKey(getObjectSize(obj), obj!!::class.java)
        pools[key]?.offer(obj)
    }
}

// 3. ViewModel 数据流优化 
class TasksViewModel : ViewModel() {
    val uiState: StateFlow<TasksUiState> = combine(
        _filterUiInfo, _isLoading, _userMessage
    ) { ... }
    .stateIn(
        scope = viewModelScope,
        started = WhileUiSubscribed,  // UI订阅时才激活
        initialValue = TasksUiState(isLoading = true)
    )
}
```

## 二、系统级内存管理：LMK/lmkd 机制

### 2.1 演进历程

| 版本 | 机制 | 特点 |
|------|------|------|
| Android 4.x 之前 | Kernel LMK | 内核驱动，基于 minfree 水位线 |
| Android 9.0+ | Userspace lmkd | 用户空间守护进程，基于 PSI 压力检测  |

### 2.2 lmkd 核心机制（Android 9+）

```cpp
// lmkd 初始化 PSI 监控
static bool init_psi_monitors() {
    bool use_new_strategy = low_ram_device || !use_minfree_levels;
    
    // 配置 PSI 阈值
    psi_thresholds[VMPRESS_LEVEL_LOW].threshold_ms = 0;
    psi_thresholds[VMPRESS_LEVEL_MEDIUM].threshold_ms = psi_partial_stall_ms;
    psi_thresholds[VMPRESS_LEVEL_CRITICAL].threshold_ms = psi_complete_stall_ms;
    
    // 注册 epoll 监听 /proc/pressure/memory
    init_mp_psi(VMPRESS_LEVEL_MEDIUM, use_new_strategy);
    init_mp_psi(VMPRESS_LEVEL_CRITICAL, use_new_strategy);
}

// PSI 事件处理：决定是否查杀进程
static void mp_event_psi(int data, uint32_t events) {
    // 1. 解析内存状态
    vmstat_parse(&vs);
    meminfo_parse(&mi);
    
    // 2. 计算抖动率（thrashing）
    thrashing = (workingset_refault_file - init_ws_refault) * 100 / base_file_lru;
    
    // 3. 确定查杀原因
    if (swap_is_low && thrashing > thrashing_limit) {
        kill_reason = LOW_SWAP_AND_THRASHING;
        min_score_adj = PERCEPTIBLE_APP_ADJ + 1;
    } else if (wmark <= WMARK_HIGH && thrashing > thrashing_limit) {
        kill_reason = LOW_MEM_AND_THRASHING;
    }
    // ... 其他条件判断
    
    // 4. 执行查杀
    if (kill_reason != NONE) {
        int pages_freed = find_and_kill_process(min_score_adj, ...);
    }
}
```

### 2.3 oom_score_adj 等级表 

| 等级 | 值 | 进程类型 | 查杀优先级 |
|------|-----|---------|-----------|
| `NATIVE_ADJ` | -1000 | init, system_server | 绝不查杀 |
| `SYSTEM_ADJ` | -900 | 系统进程 | 绝不查杀 |
| `PERSISTENT_PROC_ADJ` | -800 | 持久化系统应用 | 极低 |
| `PERSISTENT_SERVICE_ADJ` | -700 | 持久化 Service | 极低 |
| `FOREGROUND_APP_ADJ` | 0 | 前台应用 | 低 |
| `VISIBLE_APP_ADJ` | 1 | 可见应用 | 中 |
| `PERCEPTIBLE_APP_ADJ` | 2 | 可感知应用（音乐播放等） | 中 |
| `BACKGROUND_APP_ADJ` | 4 | 后台应用 | 高 |
| `CACHED_APP_MIN_ADJ` | 9 | 缓存应用 | 极高 |
| `CACHED_APP_MAX_ADJ` | 16 | 空进程 | 最先查杀 |

### 2.4 AMS 设置 oom_adj 流程 

```java
// ProcessList.java
public static void setOomAdj(int pid, int uid, int amt) {
    if (amt == UNKNOWN_ADJ) return;
    
    ByteBuffer buf = ByteBuffer.allocate(4 * 4);
    buf.putInt(LMK_PROCPRIO);
    buf.putInt(pid);
    buf.putInt(uid);
    buf.putInt(amt);
    
    // 通过 socket 写入 lmkd
    writeLmkd(buf, null);
}
```

## 三、内存泄漏检测工具

### 3.1 LeakCanary 原理与使用 

**核心机制**：
1. **弱引用监控**：创建 `WeakReference` 关联 `ReferenceQueue`
2. **触发 GC**：等待主线程空闲后触发 `Runtime.getRuntime().gc()`
3. **泄漏判定**：GC 后若对象仍未进入引用队列，则判定为泄漏
4. **堆转储分析**：生成 HPROF 文件，使用 Shark 库分析引用链

```kotlin
// 集成（2.0+ 无需初始化）
dependencies {
    debugImplementation 'com.squareup.leakcanary:leakcanary-android:2.10'
    releaseImplementation 'com.squareup.leakcanary:leakcanary-android-no-op:2.10'
}

// 自定义监控
class ObjectWatcher {
    private val watchedObjects = mutableMapOf<String, WeakReference<Any>>()
    private val queue = ReferenceQueue<Any>()
    
    fun watch(obj: Any, description: String) {
        val weakRef = WeakReference(obj, queue)
        watchedObjects[description] = weakRef
        
        // 延迟检查
        lifecycleScope.launch {
            delay(5000)  // 5秒后检查
            ensureGone(weakRef, description)
        }
    }
    
    private fun ensureGone(weakRef: WeakReference<Any>, desc: String) {
        Runtime.getRuntime().gc()
        if (weakRef.get() != null) {
            // 生成泄漏报告
            onLeakDetected(desc, weakRef)
        }
    }
}
```

### 3.2 工具对比

| 工具 | 适用场景 | 特点 |
|------|---------|------|
| **LeakCanary** | 开发阶段自动检测 | 低侵入、自动通知、引用链可视化  |

## 四、实战优化检查清单

### 4.1 开发阶段

```markdown
□ 使用 LeakCanary 自动检测 Activity/Fragment 泄漏
□ 图片加载使用 Glide/Picasso，设置合理采样率
□ 避免在 onDraw 中创建对象，使用 Path/RectF 缓存
□ 使用 ViewModel + LiveData/StateFlow 管理数据
□ 及时注销监听器（LocationManager、SensorManager）
□ 使用 WeakReference 持有 Context 引用
□ 避免使用静态变量持有 Activity 实例
```

### 4.2 系统级调优（Framework 开发）

```cpp
// 1. 调整 lmkd 参数（device.mk）
```

## 五、总结

| 层级 | 优化重点 | 关键技术 |
|------|---------|---------|
| **应用架构** | 组件生命周期管理 | ViewModel、协程作用域、内存感知加载 |
| **代码实现** | 避免内存泄漏、减少对象分配 | LeakCanary、对象池、弱引用 |
| **资源管理** | 图片/字符串优化 | 采样压缩、VectorDrawable、字符串池 |
| **系统机制** | 进程优先级与查杀策略 | lmkd、PSI、oom_score_adj 调优 |

内存优化是 Android 性能优化的核心，需要**开发阶段预防（LeakCanary）+ 运行时监控（Profiler）+ 系统级调优（lmkd）** 的全链路策略 。
